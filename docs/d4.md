## Piano e decisioni approvate

1. Storage: helper privati per inserimento DataFrame e registri, colonne dallo
   schema esistente, null/scalari NumPy adattati per SQLite. Connessione ricevuta,
   nessun commit interno; transazioni, provenienza, metadati sequenze, lock/retry
   e API di dominio conservati.
2. Acquisizione: conversione comune a numero finito con entrambi i nomi pubblici;
   `_safe_float` separata. Ricerca comune DSOL/OLOC per radici/glob con selezioni
   e ordinamento invariati. Esiti strutturati già presenti riutilizzati; nessuna
   cache, cambiamento FITS o ottimizzazione D5.
3. Esecuzione: preflight, preparazione risorse e consolidamento separati dal main;
   wrapper/import pubblici compatibili. Riutilizzare configurazione normalizzata
   e store; mantenere seconda lettura dopo le protezioni, bootstrap leggero e
   import differito del plotting.
4. Plotting: moduli privati QC/DSOL/OLOC/DETLIN e supporto comune; interfaccia
   `plotting` compatibile. Registro statico dei dieci renderer consultabile senza
   Matplotlib, dataset espliciti e adattatore OLOC con due frame. Selezioni, layout,
   ordine, isolamento errori e riepiloghi progressivi conservati. Rimuovere codice
   morto, mantenere `processing` importabile.

Versione finale prevista 1.9.0, schema 1; nessuna nuova opzione YAML/CLI o modifica
ai formati dei manifesti/JSON. Nessuna modifica scientifica, ORM o codice YAML.
